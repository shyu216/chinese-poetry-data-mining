## Bug fix：console `Unexpected token '<', "<!DOCTYPE"... is not valid JSON`（useMetadataLoader:126）
- 根因：`web/public/data/preprocessed/` **从未创建**。真实诗词数据在 `results/preprocessed/`（334 文件 / 161MB：`poems_chunk_meta.json` + `poems_chunk_XXXX.csv`）。app 经 `BASE_URL + 'data/preprocessed/...'` 请求，Vite 找不到 → SPA fallback 返回 `index.html`（text/html），`response.json()` 抛错。
- 关键约束：`web/public/data/` 在 `.gitignore`（项目本地数据家，README L53 确认数据来源为 `public/data`；author_v2/wordcount_v2/poem_index/author_clusters/keyword_index/fasttext + 顶层 `hash-manifest.json` 均已就位）。preprocessed 是唯一缺失目录。
- 修复：① `node fs.cp` 复制 `results/preprocessed` → `web/public/data/preprocessed`（334 文件，gitignored 不污染仓库，dev+prod 均生效）。② `useMetadataLoader.ts` fetch 后加 content-type 守卫：若返回非 JSON（即 SPA fallback HTML）抛清晰错误「expected JSON but got ... (asset missing from public/data?)」，取代晦涩的 `<!DOCTYPE` 解析错。
- 验证（HTTP 层，即报错原点）：复制后 `GET /chinese-poetry-data-mining/data/preprocessed/poems_chunk_meta.json` 由 `200 text/html` 变为 `200 application/json`；5 个 metadata/chunk URL 全部正确 content-type；grep 全代码 `data/` fetch 目标均存在 → 无其他缺失端点。Vite public 中间件按请求读盘，新文件**无需重启 dev server**，用户刷新浏览器即可消除报错。
